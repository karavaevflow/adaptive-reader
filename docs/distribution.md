# Distribution, installation and updates

## Current signing status

Candidate builds are universal (Apple silicon and Intel), target macOS 15.0+, use the stable `com.karavaevflow.AdaptiveReader` identity, and have a local ad-hoc signature. **They are not Developer ID signed or notarized.** A passing local codesign check is not an Apple trust/notarization assessment. Exact tested OS versions and open stable gates are in [v1.0 acceptance](v1.0.md).

Download only the intended repository release and compare its SHA-256 sidecar before expanding. Each archive includes the app, source/build metadata, actual signing status, acceptance report, changelog, privacy/security notes and code/dependency licenses. Move the app to your chosen local application folder.

macOS may block a direct-download candidate. Review the source/signing status and Apple's [Safely open apps on your Mac](https://support.apple.com/en-us/102445) instructions. If you knowingly trust that specific build, macOS may offer a per-app **Open Anyway** approval under System Settings → Privacy & Security. The project does not disable Gatekeeper, remove quarantine metadata, or provide a protection-bypass command. Do not proceed with an app macOS identifies as malicious or damaged; verify the archive and report the error instead.

A fresh CI account tests extraction, the unquarantined production app, native import and offline reading. It does not simulate a browser download or claim Gatekeeper will approve the build automatically.

## Update and preserve data

Quit Adaptive before replacing its app bundle. Keep the same application identity and retain the library. Managed sources and user records normally live at:

```text
~/Library/Containers/com.karavaevflow.AdaptiveReader/Data/Library/Application Support/AdaptiveReader
```

Preferences/window state also live in the application's sandbox preferences. API secrets are in Keychain, outside library JSON. Linked books remain in their selected external locations and may need reauthorization after moving to another Mac.

Before a candidate update, copy the library and preferences to a separate backup while the app is closed; also back up linked originals. Keep that backup until you have checked sources, positions, notes and links in the new app. Never replace your only copy with an unvalidated archive. Reinstalling or replacing the app does not require deleting its library. Downgrading across a future schema is not promised; unfamiliar records produce explicit errors rather than a silent reset.

The frozen v0.6 corpus tests both formats and all reader-owned record domains. It contains artificial records, never a contributor's private library. See [fixture provenance](../Research/Upgrade/v0.6/README.md).

## Reproduce a candidate

From a clean committed checkout with full Xcode selected:

```sh
swift test --no-parallel
xcodebuild -project AdaptiveReader.xcodeproj -scheme AdaptiveReader -configuration Release -destination 'generic/platform=macOS' -derivedDataPath /private/tmp/AdaptiveCandidate ONLY_ACTIVE_ARCH=NO 'ARCHS=arm64 x86_64' build
python3 scripts/package-release.py /private/tmp/AdaptiveCandidate/Build/Products/Release/AdaptiveReader.app --version v1.0.0-rc.1 --source "$(git rev-parse HEAD)" --acceptance docs/v1.0.md --output /private/tmp/AdaptiveReader-v1.0.0-rc.1.zip
```

The packager refuses an existing output/checksum, dirty or untracked production source, wrong app identity/version/minimum OS, missing licenses, a non-universal executable, an output without the sandbox or with debugger entitlements. It verifies the extracted app signature and emits BUILD.json plus a SHA-256 sidecar. This verifies the build/package chain; it does not promise byte-identical compiler outputs on different Xcode versions.

The original icon is generated by `swift scripts/make-app-icon.swift /new/path/Adaptive.iconset`, then `iconutil -c icns /new/path/Adaptive.iconset -o Sources/AdaptiveReader/Resources/AppIcon.icns`. It uses original vector artwork and no external logo/font assets.

## Publication gates

A candidate may be marked as a GitHub prerelease with its open gates disclosed. A stable `v1.0.0` release requires the release ledger to be complete, green pinned-source CI, reviewed references, performance regression analysis, offline installation/update checks, licenses, checksum and accurate signing status. Public binary source/target and CI source must agree. Never silently turn an RC into a stable tag.

A Developer ID Application identity with its private key and an authorized notarization profile would be needed for a Developer ID/notarized distribution. No such identity is installed now. Credentials are supplied through an owner's existing signing environment; they are never committed, printed or requested in chat. The current packager intentionally produces an ad-hoc build and does not make an untested notarization claim.
