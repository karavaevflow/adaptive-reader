Production-container tests refuse to run against an existing library or a normal contributor account. The app restores artificial v0.6 records through its normal file picker into an empty library; the test runner never writes protected container files. The installed app then exports a backup and imports another PDF through native dialogs. This checks old data compatibility using genuine v0.6 writer output, not an old-binary installer or a downloaded/quarantined Gatekeeper flow. Ordinary test launchers mute speech; installed production tests invoke no speech/model action.

AI remains optional/off by default and real-model evaluation remains deferred by the owner. Reader translations, per-page OCR, helper-process memory and source-format limitations remain explicit in the v0.6 report. No new promise of arbitrary-edition alignment or OCR accuracy is made.

The first production-package attempt was correctly denied by macOS when the test process tried to seed another app’s protected container. No TCC permission or sandbox entitlement was weakened. The replacement uses a real product Backup/Restore path. Exports exclude caches/provider settings/external originals; restore verifies hashes, quotas and typed records, then atomically swaps directories only for an empty library. The previous folder remains for recovery. Cancellation is cooperative and pending transfers are drained on exit.
